# Документация для Telegram-бота «Трекер фильмов»

## Сделал: Ким Владислав 2ИП-7-24

Учебный проект по технической документации: полный комплект документов для вымышленного Telegram-бота, который помогает вести список фильмов.

Бот является демонстрационным продуктом: цель проекта — не разработка, а написание документации. Все примеры, команды и API описаны так, как они работали бы в реальном продукте.

## О проекте

| | |
|---|---|
| **Тип** | Учебный проект |
| **Роль** | Технический писатель |
| **Инструменты** | Markdown, Git/GitHub, OpenAPI (Swagger), Swagger Editor |

## Задача

Подготовить документацию к продукту так, чтобы им могли пользоваться три типа читателей:

1. **Пользователь бота**: хочет быстро понять, как добавлять фильмы и ставить оценки.
2. **Разработчик, который запускает проект**: ему нужна установка, настройки и решение типичных проблем.
3. **Разработчик, который подключается по API**: ему нужны методы, параметры, примеры запросов и коды ошибок.

Отдельно нужно было показать навык редактирования: взять неудачную инструкцию и переписать её.

## Состав проекта

| Файл | Для кого | Что показывает |
|------|----------|----------------|
| [`bot-README.md`](docs/bot-README.md) | Разработчик | Структура README: описание, требования, установка, быстрый старт, таблицы команд и настроек, частые проблемы |
| [`user-guide.md`](docs/user-guide.md) | Пользователь | Пошаговые инструкции, подсказки, таблица «проблема → решение» |
| [`openapi.yaml`](docs/openapi.yaml) | Разработчик API | Описание методов в формате OpenAPI: параметры, примеры, коды ответов |
| [`before-after.md`](docs/before-after.md) | Рекрутер, редактор | Рерайт плохой инструкции с разбором изменений |

## Как я работал

1. **Определил аудиторию** и для каждой написал отдельный документ, потому что пользователю и разработчику нужна разная информация.
2. **Составил структуру** по принципам: сначала условия, потом шаги, один шаг — одно действие, результат показан примером.
3. **Описал API** в OpenAPI и проверил файл в [Swagger Editor](https://jdegre.github.io/editor/): документ открывается без ошибок и строит интерактивную страницу.
4. **Отредактировал текст**: убрал канцелярит, разбил длинные предложения на шаги, вынес предварительные условия в начало.

## Чему научился

- структурировать документацию под разные типы читателей;
- описывать REST API в формате OpenAPI;
- писать инструкции, которые можно выполнить без дополнительных вопросов;
- оформлять документы в Markdown и вести их в Git.
